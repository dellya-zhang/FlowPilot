# 项目展示与案例证据

本次展示改版让读者先理解业务任务、处理过程和可下载产物，再进入工作台。首页默认展示只读案例；原营销、客服、政策知识库与模型设置仍通过导航访问。

## 案例来源

`web/examples/case.json` 由 `scripts/capture_showcase.py` 在独立浏览器上下文中录制。运行浏览器模板的真实交互：创建需求、生成三套候选、审批第一套、导出试点、全量排重；同时录制客服咨询、申请与确认的消息记录。

本次录制得到17位试点、150位剩余用户，名单交集为0。它们是合成用户与模板运行的功能结果，不是模型实验、触达回执或业务增长成绩。在线案例只读文件，不自动创建任务、审批或提交审核；进入工作台后才按用户操作运行新任务。

CSV 保留原始 UTF-8 BOM 和 CRLF 字节；`.gitattributes` 禁止 Git 对样例 CSV 自动转换换行，保证下载文件 SHA256 与案例记录一致。

## 展示与简历的对应

概览回答“交付什么”：面向营销运营与客服的工作台，把活动目标推进到人工可审核的策略与版本绑定名单，并将政策咨询与审核申请分开。

源码映射回答“做了哪些工程工作”：LangGraph编排与并发、SQL租约恢复、版本冻结与幂等、BM25检索及模型成本限制。在线快照不能验证这些后端机制，需结合源码、测试与独立验证报告说明。

不要把“17+150人”写成真实触达规模，不要把模板的三套候选称为真实模型输出，不要把下载名单称为已经投放。
