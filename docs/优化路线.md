# 优化路线与验收标准

本页区分现有能力与计划工作。以下条目均为待完成项，不代表已验证的能力。

## P0：模型输出的业务语义

现状：结构化字段可解析并不等于内容可投放。拒绝说明可能被包装成候选，关键词护栏可能误报，Critic 使用启发式评分。

- 为生成结果增加 `draft / clarification / refusal` 判别类型，缺少关键信息时转入澄清流程；仅 draft 可审批和导出。
- 建立固定、可版本化评测集，覆盖信息不足、无依据优惠、敏感指令、模型拒绝及合法权益描述；分别统计字段有效性、事实一致性、护栏误报/漏报和状态流转。
- 验收：拒绝与澄清结果均不能导出；合法描述不因单个关键词被误拒；评测输出逐例结论、样本数、模型与配置版本。Mock 用于确定性回归，真实模型评测须显式开启并设置费用上限。

## P1：数据库升级与基础设施集成

现状：使用 create_all 初始化；PostgreSQL、Redis、MinIO 已有配置与适配器，尚未完成组合实测。

- 引入 Alembic，提交初始版本、增量迁移及升级指南；从有历史任务与产物的旧库验证升级。
- 增加独立集成测试任务，覆盖 PostgreSQL 条件更新与租约争抢、Redis 限流、MinIO 上传下载及对象缺失。
- 验收：全新安装和历史库升级均通过；迁移保留历史任务和产物关联；依赖故障给出可重试错误。集成测试与快速 Mock 回归分开报告。

## P1：身份、权限与数据边界

现状：共享 ACCESS_TOKEN 适用于单用户入口；不具备生产账号与租户隔离。

- 引入独立身份与租户键，在任务、候选、事件、客服历史和产物查询中强制应用权限；SSE 与下载路径使用相同校验。
- 为审批、晋级、导出增加操作者审计记录和可配置保留期限。
- 验收：两个租户互相无法读取或修改任务、回流、事件和产物；伪造 ID、直接下载与 SSE 访问同样受限。

## P2：跨主机协调与副作用恢复

现状：SQL 租约支持同机多 worker；文件预算锁依赖共享路径，MODEL_CONCURRENCY 按 worker 生效。恢复会重跑整次生成，不保证外部调用精确一次。

- 将预算预留、调用名额和并发许可迁移到集中式原子存储，明确超时释放及 usage 缺失时的结算规则。
- 使用数据库时间与 fencing token 管理执行权；外部请求引入幂等键或副作用日志。按实际恢复需求引入图级 checkpointer。
- 验收：两个独立主机竞争任务和预算不超额；网络分区、worker 崩溃、旧 owner 回写均有确定结果；重试不重复交付，重复模型费用风险有明确记录。

## P2：运行观测与容量边界

- 分离进程存活与数据库就绪检查；增加队列等待、执行耗时、租约接管、模型失败率及预算拒绝指标，日志关联任务与请求 ID。
- 使用独立负载机测试写入、生成、SSE 和导出；固定硬件、并发、数据规模及模型替身延迟，报告 p50/p95/p99、错误率与资源占用。
- 验收：数据库中断、慢模型、客户端断流和磁盘写满可定位；结果明确区分客户端排队和服务端处理，不从本机读取突发测试推导生产容量。

## P3：实验与交付体验

- 增加观察窗口、最小样本量及统计区间，避免依据少量模拟转化自动晋级；保留人工选择记录。
- 记录数据快照与导出版本，补充产物保留和清理策略；清理过程避开正在交付的对象。
- 验收：迟到与重复事件处理可复现；全量名单排除两臂试点用户；清理不破坏在途下载。
