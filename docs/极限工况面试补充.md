# 极限工况相关面试追问补充

1. **为什么Semaphore存在，20个请求还是全被接受？** 单活动Semaphore只限候选；路由检查len(tasks)和创建task之间有await，形成检查与使用竞态。修复方式是在任何数据库等待前用锁预留容量，finally释放名额。复现时容量2却接受20，修复后仅2个。
2. **取消asyncio父任务就安全了吗？** 不是。as_completed内部子task不会因为外层协程取消就自动全部停止；要保存task引用，在finally里cancel+gather。远程请求及to_thread底层线程也未必真正停止，仍要费用对账和孤立对象清理。
3. **为何有SHA256还可能下载坏数据？** 把哈希存在数据库和返回头，不等于读取时校验。已加入下载和试点排重时比对内容哈希；故障测试篡改文件后返回503，状态不推进。
4. **数据库事务是否覆盖文件系统？** 不覆盖。临时文件+replace保证本地单文件可见性，不能保证与数据库同时提交。崩溃可遗留对象；需产物状态、幂等对象键及回收任务。
5. **事务为何还要包含事件？** 如果状态先提交而事件后提交失败，客户端可能收到错误但任务已经推进。queued、审批及交付事件已与对应状态共同提交，但数据库与执行调度仍无跨进程事务，进程退出仍靠恢复。
6. **A/B晋级后为何不能再调用普通pilot？** 会生成独立于两臂的第三批试点，破坏已暴露人群的含义。状态允许不代表业务路径允许，要检查是否属于实验。
7. **500个请求全部成功能写高并发吗？** 只能写本机有限突发测试。连接池32，客户端p95约1.84秒包含排队，不能当服务端时延，更不能推导生产容量或真实模型吞吐。
8. **为何SSE会耗尽连接池？** 路由初始查询打开事务，如果把依赖session留到流关闭就会长期占连接；已在流开始前释放，并仅用短session轮询。40次断连通过不等于数千长连接验证。
9. **为什么要实际kill进程？** 用数据库手工设GENERATING只能测恢复分支；真实终止才能覆盖OS进程退出、连接释放和未完成任务。已强杀慢worker并以同一DB重启，恢复3个唯一候选，但仍是整任务重跑。
10. **怎样证明没有消耗真实模型？** 故障测试入口强制AI_PROVIDER=mock或MockTransport，临时审计文件不存在；现有真实调用账本仍是15次。本轮不利用供应商限流或制造收费流量。
11. **还有什么没测？** PG/Redis/MinIO真实故障、多副本、长时间soak、磁盘真正写满、机器断电、网络半开与代理缓冲。这些不能用适配层抛OSError或本机HTTP突发替代。
