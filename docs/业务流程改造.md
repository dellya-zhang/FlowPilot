# 业务流程改造

- 普通方案：生成候选、冻结审批版本、直接全量交付。旧版 pilot/finalize 接口保留用于历史案例；新页面使用 full。
- A/B：互斥客群、模拟事件回流、显式结算、固化描述性推荐、人工晋级、剩余全量。未到观察期时须填写模拟原因；结算后拒绝新反馈。旧版 promote 调用保持兼容，工作台要求 require_finalized=true。
- 交付前重新检查冻结文案和实际名单的预算；仍使用人工确认的预览文案，不声称实现正式文案生成子图或全部生产合规规则。
- 客服：独立低成本规则粗筛、优先级决策、安全 fallback、待确认与人工转接建议。规则命中记录随本轮响应展示；待确认内容保存在已有 session 字段。非真实订单、工单或退款。历史返回最近 50 条；持久化完整决策审计、模型工具循环、行业包和客服 SSE 尚未实现。
- 前端：活动搜索与状态汇总、普通交付和实验结算操作、新会话与处理记录。在线浏览器模式仍为模拟，客服决策链与本地后端尚有差异。

本次修改不包含外部原始资料、企业内部接口、数据或测试指标。尚未执行完整回归及浏览器验收。
