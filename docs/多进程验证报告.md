# 多进程验证报告

日期：2026-11-14。本轮无真实模型调用。使用3个独立Uvicorn服务进程、相同SQLite数据库和本地对象目录，另用8个独立Python进程竞争共享费用名额。

## 已实现的改动

- 新增execution_leases表，不修改既有campaigns表结构。认领时通过SQL条件更新/唯一主键竞争取得随机owner令牌；过期租约才可接管。
- 心跳按TTL的1/3续期。候选、事件和最终状态写入前，以owner及租约有效期进行条件更新，阻止旧执行者提交数据。
- 后台恢复扫描定期检查未被有效租约持有的GENERATING任务，并按本worker剩余容量分批调度。某worker退出后，存活worker无需重启即可接管。
- 同机启动初始化加跨进程锁，避免并发建表/合成客户重复初始化。
- 费用日志使用独立.lock文件、操作系统文件锁、fsync及临时文件原子替换。预留、结算和结算去重在同一锁下执行，日志损坏则拒绝继续。
- 费用文件操作放入线程，不在事件循环内同步等待跨进程锁；历史15次真实调用的日志保留，不重置授权。

## 实际验证

| 场景 | 结果 |
|---|---|
| 3个服务同时启动 | 都就绪，合成客户仍恰好500条 |
| 慢worker执行超过租约TTL | 心跳续期有效，其他worker未重复执行，generation.started只有1条 |
| 强杀慢worker | 存活worker约1.641秒接管；两次started对应不同owner，最终只有1次完成和3个唯一variant |
| 60个跨进程重复生成 | 只有1次请求接受 |
| 60个跨进程竞争审批 | 只有1次审批成功 |
| 60个跨进程并发导出 | 全部成功，复用同一artifact |
| 8个独立进程竞争2次费用名额 | 恰好2个接受、6个拒绝，共4条完整账本事件 |
| 旧owner尝试写入 | 被fence拒绝，事务回滚；旧owner不能续期或释放新owner租约 |

离线回归53 passed；原有HTTP突发、强杀恢复等回归也执行。可核对原始结果见multiprocess-results.json。

## 复现

```powershell
.venv/Scripts/python -m pytest -q
.venv/Scripts/python scripts/multiprocess_check.py
```

脚本会创建临时数据库，启动并清理独立服务进程，强制Mock，不消费模型Key。

单机多worker可以在数据库和artifact目录共享的前提下尝试：

```powershell
uvicorn app.main:app --workers 3
```

本次重点验证的是3个独立服务进程互访和故障接管，未将其冒充跨主机或跨地域压测。

## 保留的边界

1. **只验证同机共享文件系统。** 文件锁和初始化锁不适用于未经验证的NFS、不同主机本地盘或不共享的容器卷。跨主机应使用迁移作业、数据库账本或Redis原子操作。
2. **时钟依赖。** 租约使用本机time.time，已测进程共享同一系统时钟；没有验证跨主机时钟偏移或系统时钟跳变。跨主机应统一数据库时间或专门协调机制。
3. **执行不是精确一次。** 旧执行者无法提交数据库，不等于已发出的模型请求不计费；接管会重跑整次生成，可能再次调用模型。预算预留限制费用，但不消除重复推理。
4. **全局容量的范围。** MODEL_CONCURRENCY和MAX_ACTIVE_CAMPAIGNS仍是每worker上限；3个worker的总并发可能是单worker上限的3倍。共享费用名额跨同机进程生效，但不等同于集群级模型并发控制。
5. **续期失败。** 数据库长时间阻塞或心跳失败会取消执行，随后等租约过期接管。没有验证所有数据库故障组合或长期活锁；日志和指标应监控续期失败。
6. **数据库与外部对象。** 仍没有跨系统事务、外部工具幂等键或孤立对象回收任务。
7. **SQLite不是分布式数据库。** 通过本机测试不代表PostgreSQL/Redis/MinIO已经联调，或适合大规模多副本。
8. **schema版本。** 当前create_all可创建新增租约表，但不替代版本化迁移；生产环境不应让所有worker负责建表。
